## 소리 증거와 한계

- 일반/빵 타격의 4kHz 이상 에너지 비율은 대략 40–54%에서 0.03–0.04%로 감소했다.
  곰팡이 타격도 약 5.5–7.6%에서 0.02% 수준으로 감소했다. 이는 덜 날카로운 소리를 만들기 위한
  설계 선택이며 실제 기기에서의 사람 청감 평가를 대신하지 않는다.
- 타격의 인접 샘플 변화도 감소했다. 수정 전·후 모두 원본 WAV의 full-scale clipping은 0이었다.
  따라서 기존 현상을 단순히 디지털 클리핑 탓이라고 쓰지 않는다.
- 독립 타격 12회·운반·정찰 cue 이후 실제 정상 속도 r08을 35초 실행했다. 약 42.69초의 유효 녹음:
  Master peak **−2.54 dBFS**, SFX peak **−2.97 dBFS**, full-scale sample **0**, 음성 강제 교체 **0**,
  누락된 cue/리소스 **0**. rate-limit으로 생긴 의도된 gap/group 생략은 5/3회다.
- 이 PC의 WASAPI 출력은 7.1이었다. AudioEffectRecord가 마지막 스테레오 쌍을 반환해 처음 두
  시도의 녹음은 무음이었다. 이를 증거에서 제외하고 검증 전용 플레이어만 모든 쌍에 동일 신호를
  복사해 재녹음했다. 배포 게임의 믹스 라우팅과 시스템 출력 장치·설정은 바꾸지 않았다.
  엔진 구현 참고: [Record instance](https://github.com/godotengine/godot/blob/master/servers/audio/effects/audio_effect_record.cpp).
- [자산 전후 분석](quality-20261105/audio-assets.json), [엔진 녹음 조건·통계](quality-20261105/audio-mix.json),
  [유효 녹음 파형 측정](quality-20261105/audio-waveform.json). 원시 WAV는 로컬 build/quality-20261104/audio-visible-fixed에 보존했다.
- 실제 헤드셋·폰 스피커에서 사람이 듣는 AUD-03은 여전히 **NOT_TESTED**다. 백신·드라이버·서비스와
  검사 제외 설정을 변경하지 않았다. 커널 덤프 원인을 이 게임 검사로 판정하지 않는다.

## 비용 비교

동일 PC RTX 2070 SUPER, Godot 4.7.2 Compatibility, 1280×720, 새 저장의 r01 자동 플레이,
3초/9초 캡처를 한 실행씩 직렬 측정했다. 이는 짧은 데스크톱 검사이며 폰 성능 인증이 아니다.

| 측정 | v0.1.1 EXE | 수정 소스 |
| --- | --- | --- |
| FPS / p95 frame | 60 / 약 16.67ms | 60 / 약 16.67ms |
| draw calls (3s/9s) | 117 / 114 | 140 / 141 |
| texture monitor bytes | 16,620,491 | 16,050,639 |
| sim max (짧은 실행) | 0.309ms | 0.440ms |

미니맵·제분소 표현으로 draw call은 약 27개 늘었다. 이를 성능 개선으로 포장하지 않는다.
사용하지 않는 기존 biome 페이지를 해제하고, 새 PNG는 Godot에서 절반 크기(1086×362)로 가져와
텍스처 비용을 제어했다. 원본 RGBA는 그대로 보존한다. 새 효과음의 resident SFX는 약 257KB이며
기준 약 207KB보다 약 50KB 늘었다. 새 렌더용 viewport·후처리 shader·외부 패키지는 없다.
화면 읽기를 동반한 motion_probe의 FPS는 성능 비교에서 제외한다.

## 회귀 검사

- 수락 검사: **156 PASS / 0 FAIL / 2 NOT_TESTED** (실물 Android와 사람 청감).
- UI: **3,415 PASS / 0 FAIL**. 실제 엔진 UI 통합: **49 PASS / 0 FAIL**.
- 기존 수정 회귀: **29 PASS / 0 FAIL**. 새 headless 입력·운반·배치: **57 PASS / 0 FAIL**.
- 최종 실제 화면 입력·움직임: 640×360 / 1280×720 각각 **71 PASS / 0 FAIL**.
- 새 테스트는 마우스 누름과 터치 에뮬레이션이 섞인 뒤 hover로 계속 정찰하던 경우도 재현한다.
- 기존 UI/통합 테스트는 종료 순간 폰트/오디오 ObjectDB 경고가 남는다. 새 테스트는 Audio.prepare_quit
  뒤 대기해 정상 종료한다. 이를 배포 게임의 실행 실패로 바꾸어 주장하지 않는다.
- 검사는 private APPDATA로 실행했고, 보이는 창은 DISPLAY2 위치 증거를 남겼다.
  실제 사용자 저장 파일과 기존 미검증 WIP는 포함하지 않았다.
