## 2. r01 안내 순서 (deploy → move → worker → base) 시간표
근거 코드: src/gameplay/tutorial_director.gd 50–61(보이기→다음 호출에서 완료 검사), 66(`tut_move_hero` 조건 항상 참), **67(`tut_deploy_unit` = `moved or sim.t >= 4.0`)**, 68(`tut_buy_worker` = 출병 1회 이상 그리고 밀가루 ≥ 40), 83–84(완료 = 움직임 / 출병 1회), 98(이동·출병·고용 시간 제한 `ACTION_TIMEOUT` 20초). battle.gd 226–233: 매 프레임 `_step_tutorial()`이 이벤트 처리보다 먼저 돌고, `moved`는 ◀▶를 누르는 동안 켜진다. 그래서 출병은 다음 프레임에 완료로 보이고, 움직임은 같은 프레임에 보인다. 경제: r01 시작 밀가루 60, 수입 4/s, 식빵병 30, 제빵사 40.

### 2.1 확정: 출병 안내는 "처음부터 바로"가 아니라 **영웅을 안 움직이면 4.0초**에 뜬다
- 01→02 R15는 "첫 단계가 되었으니 조건이 처음부터 참이라 바로 뜬다"고 적었다. 코드 67행은 `moved or sim.t >= 4.0`이다. 0초에는 `moved = false`, `t = 0`이라 거짓이다.
- 그래서 출병 안내가 뜨는 때는 (a) ◀▶를 누른 프레임, 또는 (b) 그런 일이 없으면 시뮬 시간 4.0초다(모형: 241번째 1/60초 단계 = 4.017초, 1/60을 더해 가는 부동소수 때문에 240번째에는 4.0 미만).
- 4.0초는 첫 적(트리클 6초)보다는 앞서고, 옛 순서(영웅을 안 움직이면 20초)보다 16초 빠르다. 하지만 01이 의도한 0초는 아니다.

### 2.4 읽은 결과
1. 새 순서는 출병을 안 하는 사람(P1a)에게 출병 안내를 20초 → 4초로 앞당긴다. D44의 목적에는 맞는다.
2. 그러나 **영웅을 안 움직이는 사람은 고용 안내가 이동 안내 20초 뒤로 밀린다**(P1b 26.1초, P2b 24.1초). 옛 순서보다 4초 늦다. r01 첫 웨이브는 12초, 둘째는 40초다.
3. 4초 전에 출병한 사람은 출병 안내가 1프레임 깜빡인다. 11의 CR-007(이미 한 행동의 안내가 1프레임 깜빡임, 02 R3)과 같은 원인이고, 새 순서에서는 "바로 출병"이라는 흔한 행동에서 생긴다. CR-007의 통과 기준(트리거 때 이미 완료면 보이지 않고 done에만 기록)이 이 경우도 고친다.
4. 출병을 한 번도 안 하면 고용·둥지 안내는 끝까지 안 뜬다(P1a). 옛 순서도 같았다.

C에서는 이동 안내가 고용 뒤(약 4.6초)에 나온다. r01은 영웅을 안 움직여도 이길 수 있는 튜토리얼이라(ROUNDS.md r01, D24a) 이동 안내가 셋째여도 손해가 작다고 본다. 사람이 정말 그렇게 받아들이는지는 사람 시험(D11) 몫이다.
