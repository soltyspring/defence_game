# Fable 아트 제작 지시 — 먼저 한 화면을 완성된 게임으로 만든다

2026-11-12 사용자 요청: “그래픽 더 시키고 싶은데 진짜 지금도 너무 별로야. 진짜 게임처럼 만들어야 하는데.”

## 이번 작업의 결과물

너는 이 게임의 아트 디렉터이자 실제 제작자다. **R01의 아군 기지 → 중앙 교전 → 적 둥지까지 이어지는 한 전장을 새 아트로 완성하고, 기존 전투가 실제로 돌아가는 개발용 장면에 적용해라.** 보고서·팔레트·큰 콘셉트 그림만 만들고 끝내지 않는다. 게임 크기에서 보이는 그림과 움직임이 결과물이다.

전체 40라운드에 비슷한 도형을 늘리는 작업은 중단한다. 먼저 대표 화면을 완성한다. 첫 결과를 사용자가 확인하기 전에는 40라운드 전체 교체로 확대하지 않는다. 이는 첫 작업을 시작하기 전 승인을 다시 받으라는 뜻이 아니다. 아래 범위는 지금 제작하고 검증한다.

## 1. 지금 화면이 부족한 이유

- 지형이 긴 수평 띠로 나뉘고, 물체가 단순 사각형·삼각형으로 붙어 있어 게임 세계보다 도형 시연처럼 보인다.
- 배경 건물·기지·캐릭터의 픽셀 밀도와 묘사 수준이 다르다. 세밀한 성채를 평평한 마을 앞에 붙이는 것으로 통일되지 않는다.
- 아군 기지는 빵집보다 중세 성처럼 보인다. 적 둥지도 차가운 덩어리만으로는 고유한 생물이 되지 않는다.
- 카메라가 실제 싸움을 비추면 랜드마크가 화면 밖으로 나가거나 확대되어 잘린다. 전체 맵 목업에서만 멋진 배경은 실패다.
- 캐릭터는 설명 없이는 빵의 종류·병과·공격 동작이 충분히 읽히지 않는다. 색이나 장식만 늘리는 방식은 밀집전에서 더 나빠진다.
- 배경을 저대비로 만드는 것은 디테일을 전부 없애라는 뜻이 아니다. 재질과 원근은 유지하고, 전투 실루엣과 위험 표시 주변에만 시각적 여백을 만든다.

이 판단은 고쳐야 할 가설이다. 실제 최신 캡처를 보며 틀린 부분은 근거를 붙여 정정해도 된다. 예쁜 단어로 평가를 덮지 않는다.

## 2. 읽기와 작업 범위 — 탐색에 시간을 소모하지 않는다

첫 읽기는 아래로 제한한다. 전체 저장소·수천 줄 세션 기록·경제 프로브를 다시 읽지 않는다.

1. `AGENTS.md`, 이 문서, `docs/design/FABLE_HANDOFF.md`의 현재 상태만 읽는다.
2. `git status --short`, `git log -6 --oneline`과 아래 아트 관련 파일의 필요한 함수만 확인한다.
3. `docs/art/fable52/backdrop/rounds_all_r01-r40_fight_half-size.png`와 R01·R10 교전 캡처를 실제 이미지로 본다.
4. 있으면 `build/polish/captures/ko-640x360/menu.png`, `r09.png`, `r10.png`, `r31.png`, `r40-hud-stress.png`를 본다. 이 파일들은 Codex 작업 중 캡처이며 커밋 기준과 다를 수 있다.
5. `data/units/units.json`의 영웅·식빵병·기본 적과 `assets/atlases/char_player.json`, `bases.json`의 해당 프레임 크기·피벗·애니메이션 계약만 확인한다.
6. 적용 연결은 `src/gameplay/lane_backdrop.gd`, `battle_view.gd`, `backdrop_scenes.gd`, `pixel_camera.gd`에서 필요한 부분만 읽는다. 전체 내용을 반복 읽지 않는다.

추가 읽기는 실제 의존성이나 실패 원인을 해결하는 경우에만 한다. 읽은 사실과 작업 시작점을 `docs/art/release_slice/HANDOFF.md`에 짧게 남겨 다음 세션에서 재탐색하지 않게 한다.

### Codex와 병행 작업하는 경계

Codex는 설정창·HUD·음악·기존 배경 연결·EXE를 수정 중이다. 같은 작업 트리에서 아래 기존 파일을 고치면 충돌한다.

- 이번 Fable의 쓰기 범위: `assets/art/release_slice/**`, `tools/art/release_slice/**`, `src/art_preview/**`, `scenes/art_preview/**`, `tests/art_preview/**`, `docs/art/release_slice/**`.
- 기존 `src/ui/**`, `src/audio/**`, `src/gameplay/**`, `assets/atlases/**`, `assets/manifest.json`, `data/**`, `project.godot`, `export_presets.cfg`, `tools/art/bases.py`는 읽기만 한다.
- 원본 전투 코드를 복제해서 별도 게임을 만들지 않는다. 개발용 장면에서 기존 `App.start_round`/전투·카메라를 사용하고, 새 그림을 연결하는 어댑터를 전용 경로에 만든다. 그림만 교체하며 판정·능력치·입력·세이브는 유지한다.
- 새 아틀라스는 전용 경로에 만들고, 기존 계약과의 매핑을 `integration.json`으로 제공한다. 기존 런타임에 어댑터 연결이 불가능하면 필요한 최소 연결 수정안을 `INTEGRATION.md`에 함수·삽입 위치·이유로 남긴다. 다른 파일을 몰래 고치지 않는다.
- 기본 실행에서 아직 새 아트가 안 나오는 경우에는 “실게임 전체 적용 완료”라고 쓰지 않는다. 개발용 실제 전투에 적용한 범위와 Codex 통합이 남은 부분을 구분한다.

## 3. 아트 방향 — 따뜻한 제빵 마을에 살아 있는 곰팡이가 침투한다

목표는 손으로 다듬은 2D 픽셀 아트다. 귀엽지만 유아용 아이콘 모음처럼 보이지 않게, 둥글고 묵직한 덩어리와 분명한 행동 실루엣을 만든다. 화면 전체가 같은 사람이 그린 것처럼 보여야 한다.

- 아군: 구운 빵 껍질, 밀가루 묻은 나무, 크림색 반죽, 벽돌 화덕, 낡은 붉은 천. 빵 재질과 제빵 도구가 읽혀야 한다.
- 적: 부풀고 찢어진 갓, 젖은 균사, 비대칭 군집, 낮은 채도의 청록·회녹. 위험 발동 색과 배경의 발광 장식은 구분한다.
- 광원은 한 방향으로 통일하고 물체의 접지 그림자, 앞뒤 가림, 재질별 하이라이트를 정한다.
- 빵·나무·돌·곰팡이는 동일한 사각형에 색만 바꿔 쓰지 않는다. 작은 해상도에서도 다른 표면으로 읽힐 만큼 형태와 명암 묶음을 다르게 만든다.
- 외곽선·픽셀 단위·그림자 길이·대비 단계를 먼저 대표 물체에 적용한 뒤 주변 물체로 확장한다. 기존 스타일 규칙도 나쁜 결과를 고착한다면 전용 작업 안에서 개선하고 차이를 기록한다.
- 카메라 확대와 실제 렌더 배율을 먼저 확인한다. 큰 그림을 nearest 축소한 잡음이나, 제각각인 픽셀 크기를 도트 스타일이라고 부르지 않는다.

### 참고작은 화면의 원리를 조사한다

팔라독/냥코 대전쟁은 횡방향 전선과 밀집 캐릭터 구분, Kingdom Rush는 재질·색 덩어리·랜드마크, 완성도 높은 2D 픽셀 게임은 접지와 원경 깊이를 참고한다. 공식 스크린샷·영상에서 확인한 것만 기록하고 출처 URL과 영상 시간대를 붙인다. 장르가 다른 예시는 무엇만 가져오는지 명시한다. 참고 조사 문서는 1페이지 이내다.

특정 작품의 캐릭터·건물·배경 배치를 그대로 가져오지 않는다. 외부 에셋은 상업적 사용·수정·게임 및 저장소 재배포를 허용하는 라이선스를 파일별로 확인하고 출처·저작자·수정 내용을 동봉한다. 다운로드 수집에 시간을 쓰지 말고 실제로 화면을 개선하는 재료만 쓴다. 이용 가능한 이미지 도구가 있다면 사용할 수 있지만, 없는 도구를 사용했다고 주장하지 않는다.

## 4. 반드시 제작할 것

### A. 전장 배경 세트 1개 — 화면 세 구역이 하나의 장소로 이어져야 한다

**아군 기지 구역:** 거대한 성벽 대신 빵집을 요새화한 모습. 큰 화덕과 굴뚝, 둥근 빵 지붕 또는 간판, 반죽 작업장, 곡물 자루, 수레 중 화면 크기에서 효과적인 요소를 고른다. 잘 보이지 않는 소품을 전부 넣지 않는다. 제빵사가 오가는 동선과 기지 바닥의 연결이 자연스러워야 한다.

**중앙 교전 구역:** 걸을 수 있는 길의 폭·측면·접지, 밭의 큰 흐름, 비대칭 방풍림 또는 멀리 보이는 마을. 수평 띠 대신 길·완만한 둔덕·밭의 방향으로 원근을 만든다. 유닛 발과 바닥 예고 구역을 덮지 않는다. 장식이 전선에서 이동하는 적처럼 보이면 제거한다.

**적 기지 구역:** 곰팡이 숲에서 기지로 번져 들어오는 큰 균사와, 안에서 숨 쉬는 둥지. 검은 덩어리에 눈만 붙이지 말고 중심 기관·외피·바닥 뿌리의 구조를 만든다. 아군 건물을 초록색으로 칠한 변형은 금지한다.

하늘/원경/중경/전투 바닥/기지 주변을 별도 레이어로 만들되, 재사용 가능한 작은 세트로 구성한다. 라운드마다 거대한 한 장 배경을 새로 로드하는 방식은 피한다. 움직이는 구름·연기·포자는 화면당 소수만 쓰고, 움직임을 끈 상태에서도 완성된 그림이어야 한다.

### B. 두 기지의 게임용 스프라이트

- 아군 빵집 기지와 적 둥지를 각각 정상·손상·붕괴 3상태로 제작한다.
- 손상은 단순 어둡게 하기 대신 지붕/문/외피의 실제 실루엣 변화로 읽힌다. 붕괴 잔해는 공격 판정과 피격 위치를 오해시키지 않는다.
- 정상 대기 애니메이션은 연기/화덕/호흡 정도로 절제한다. 기지 전체를 계속 흔들지 않는다.
- 기존 프레임 슬롯·발 피벗·기지 좌표와 호환되는 안을 우선한다. 더 큰 그림이 필요하면 충돌 판정을 바꾸지 않고 장식의 확장 영역과 카메라 잘림 검토를 별도로 제출한다.

### C. 대표 캐릭터 3종을 같은 화풍으로 완성

영웅, 식빵병, 기본 곰팡이 적을 선정한다. 실제 ID·애니메이션은 데이터에서 확인한다.

- idle/walk/attack/hurt/death 중 기존 엔진이 실제 사용하는 모든 상태를 제작한다. 시트 한 장에 멋진 정지 자세만 만들지 않는다.
- 영웅은 얼굴·요리사 정체성·밀대 실루엣이, 식빵병은 빵 몸체·작은 장비가, 곰팡이는 비대칭 갓과 공격 방향이 읽혀야 한다.
- 걷기는 그림 전체 좌우 흔들기 대신 발의 접지와 몸의 무게 이동을 만든다. 공격은 준비 → 접촉 → 회복으로 읽히되 기존 `hit_frame`과 공격 주기는 바꾸지 않는다.
- 같은 유닛 8명이 겹친 장면과 양 진영이 맞붙는 장면에서 머리·무기·발 위치를 구분한다. 대형 알고리즘 변경으로 아트 결함을 숨기지 않는다.
- 몸체 크기·피벗·프레임 수·fps·hit_frame을 유지한다. 계약 변경이 꼭 필요하면 기존 파일 대신 별도 제안에 적는다.

### D. 완성 화면으로 쓸 타이틀 구성안 1개

A–C 제작물을 재사용해 빵집 마을과 침투하는 둥지가 보이는 메뉴용 구성을 만든다. 가운데 로고·시작 버튼 공간을 미리 비운다. 별도 대형 일러스트와 새 화풍을 추가하지 않는다. 기존 로고·글꼴·버튼 코드는 바꾸지 않고 개발용 장면에 현재 UI를 얹어 보여준다. 그림에 글자나 가짜 버튼을 구워 넣지 않는다.

## 5. 제작 순서와 완료 기준

1. 실제 화면과 카메라 배율 확인 → 지적할 결함 5개와 한 장짜리 스타일 기준 작성.
2. 아군 기지·중앙 교전·적 둥지의 핵심 색 덩어리와 실루엣 제작 → 실제 크기에서 비교.
3. 대표 캐릭터 3종, 재질, 기지 상태, 절제된 애니메이션을 완성.
4. 전용 개발 장면에서 **기존 전투 시뮬레이션을 실행하며** 새 아트를 적용. 같은 카메라·시드·해상도로 전후 캡처.
5. 스스로 가장 약한 장면을 골라 한 번 더 수정하고 같은 조건에서 다시 캡처. 결과가 여전히 미달이면 그 장면과 이유를 명시한다.
6. 타이틀 구성, 소스·아틀라스·라이선스·통합 매핑·짧은 인수인계까지 정리.

체크 목록을 통과했다고 ‘출시급’이라고 선언하지 않는다. 최종 미술 판단은 실제 화면을 보고 사용자가 한다. 네가 만들어야 하는 것은 **사용자가 판단할 만한 완성된 후보**다.

### 제출할 증거

- 640×360 실제 화면: 아군 기지, 중앙 교전, 적 둥지, 동일 캐릭터 밀집전, 적/아군 혼전, 손상 기지, 메뉴. 전후 카메라·배율·장면 상태가 같아야 한다.
- 480×270과 1280×720: 가장 혼잡한 전투와 타이틀. 화면 밖 잘림·핵심 유닛 가림을 점검한다.
- 애니메이션은 6–10초 실제 개발 장면 녹화 또는 엔진에서 출력한 프레임 열로 증명한다. 프레임 시트와 실제 게임 녹화를 구분한다.
- 흑백에서 아군/적 실루엣·위험 표시를 구분할 수 있는지 확인. 색각이나 사람 인지 검증을 자동 수치로 대체했다고 주장하지 않는다.
- 프레임 계약, atlas padding/extrusion, nearest 필터, 투명 경계, 한글 글자 영역 침범 확인.
- 텍스처 페이지 수·GPU 메모리 추정·동시 드로우콜 변화를 기록. 기존 장면 대비 신규 동시 텍스처는 우선 8MiB 이내 목표, 초과 시 실제 필요와 대안을 쓴다. 수치만 줄이느라 아트를 단순 도형으로 되돌리지 않는다.

실제 실행은 `coordination/heavy_run_detached.ps1`의 잠금 안에서, 별도 APPDATA와 가상 디스플레이 또는 헤드리스로 한다. 사용자 데스크톱을 전환·클릭하거나 보이는 창을 띄우지 않는다. 환경상 캡처 불가면 구현·아트 소스·재현 장면까지 만들고 미검증으로 표시한다. Python 목업을 실제 게임 화면이라고 부르지 않는다.

## 6. 이번에는 하지 않을 일

경제/상점/결제/라운드 수치, 저장·해금, 전투 AI·기믹, 대형 알고리즘, 설정창/HUD 배치, 챕터 음악·R40 음향, 전체 회귀와 Windows EXE 패키징은 Codex 담당이다. 이번에는 새 몬스터 수나 라운드 수를 늘리지 않는다. 기존 일반 기획 문서의 미완료 항목을 핑계로 아트 제작을 미루지 않는다.

기존 `프롬프트.md`의 과거 전투·경제 요구보다 **이 문서의 이번 작업 범위가 우선**이다. 궁금한 점을 길게 묻기보다 호환 가능한 선택으로 첫 후보를 실제 제작한다.

## 7. 파일·커밋·인수인계

전용 경로 안에 원본/생성기/atlas 및 매핑을 남긴다. 임시 사본에만 두지 말고 프로젝트 폴더에 반영한다. 다른 작업자의 변경, 로그, 엔진 바이너리, 임시 다운로드를 커밋에 넣지 않는다. 결과와 검증을 끝낸 뒤 **Fable은 자신의 명시적 파일만 로컬 커밋**하고 SHA를 보고한다. 푸시·기존 런타임 최종 통합·EXE 갱신은 Codex가 검토 후 담당한다. 이 작업에 대한 역할 분담은 일반 자동 푸시 규칙보다 우선한다.

`docs/art/release_slice/HANDOFF.md`에는 다음만 적는다: 기준 SHA, 실제 바꾼 파일, 실행 명령, 실제 캡처 위치, 미검증, 통합 접점, 가장 약한 장면, 다음에 열 파일. 변경된 파일 목록과 라이선스 출처를 빠뜨리지 않는다.

최종 보고의 첫 줄은 “대표 화면 후보를 어느 경로에서 실행해 볼 수 있는가”로 시작하고, 다음으로 실제 전후 화면을 제시한다. 문서 분량·생성기 코드량·테스트 개수로 그래픽 완성도를 설명하지 않는다.
