# 빵집 기사단: 곰팡이 디펜스 — Fable 5.2 그래픽 개편 브리프

2026-11-10 · 조사 기준 `9b730fd`와 현재 체크아웃의 HUD 코드. 저장된 캡처는 서로 다른 시점의 자료다. 아래 관찰은 캡처에 한정하며, 착수 전에 현재 빌드 기준선을 다시 찍는다.

## Fable 5.2에 가장 잘 맞는 일

**스크린샷에서 시인성을 해치는 원인을 찾고, 그 원인을 Godot의 레이어·카메라·HUD 코드까지 추적해 한 번에 고치는 일**을 먼저 맡긴다. Anthropic은 5.1 대비 코딩·추론·시각 이해가 개선됐다고 발표했다. 자체 평가 FrontierSWE v2에서 Fable 5.2는 69.9%, Fable 5.1은 56.3%, Opus 5.5는 62.3%였다. 이 수치는 코드 작업의 참고 자료이며 픽셀 아트 감각을 평가한 결과는 아니다. API 사양은 텍스트·이미지 입력에서 텍스트를 출력한다. 따라서 최종 PNG를 직접 생성하는 모델로 가정하지 말고, 비교 시안의 지시서·팔레트·타일 규칙, 기존 Python 생성기 수정, Godot 적용과 전후 QA를 맡긴다. 외부 이미지 도구를 쓴다면 그 출력은 컨셉 초안으로 보고 기존 픽셀 그리드와 아틀라스에 맞춰 정리한다.

## P0 — 전투 배경부터 다시 잡기

관찰: [Windows 전투](../qa/windows-polish/battle.png)에서 밝은 밀밭의 잔점과 반복되는 창문·처마가 화면에 넓게 깔린다. 유닛은 하단의 가는 띠에 몰린다. [R06 전후](world/evidence/captures/pair_r06_top-before_bottom-after_1x.png)에서는 개선 후 원경 깊이가 늘었지만 밭의 잔점과 일렬로 선 건물의 반복이 남는다. [보스 화면](../qa/windows-polish/boss.png)에서는 보스가 잘 보이지만 그 앞에 몰린 작은 아군과 타격 이펙트가 한 덩어리로 보인다.

1. **첫 시안: 밀밭 마을 → 곰팡이 오염지.** 좌측은 따뜻한 빵집·풍차, 중앙은 낮은 담장과 빈 공터, 우측은 낮게 깔린 포자와 비대칭 곰팡이 둥지. 풍차·빵집 굴뚝·둥지를 길 찾기 표식으로 쓰고, 건물 복제를 나열하는 대신 골목과 공터로 간격을 만든다. 적이 나타나기 전에도 어느 쪽이 아군 진영인지 형태로 구분한다.
2. **대안: 같은 지도에 해질녘/오염 팔레트.** 원경을 낮은 대비의 덩어리로 묶고 밭은 넓은 색면과 드문 볏단으로 표현한다. 전투 띠 바로 뒤에는 고대비 창문·처마·포자 줄무늬를 피한다. 따뜻한 아군과 차가운 적을 색으로 보조하되, 흑백에서도 실루엣으로 구분되게 한다.
3. **카메라와 발판.** 멀리 있는 능선은 느리게, 마을은 중간 속도, 발밑 길은 월드에 고정한다. 배경 교체만 한 안과 카메라 구도를 조정한 안을 따로 비교한다. 줌·추적·좌우 탐색에서 타일 이음새, 발 미끄러짐, 픽셀 떨림, 월드 좌표나 공격 거리 변화가 없어야 한다. `tools/art/biome.py`, `assets/atlases/biome_meadow.*`, `src/gameplay/battle_view.gd`, `src/gameplay/pixel_camera.gd`부터 확인한다. 아틀라스 계약 변경은 소비 코드와 함께 검증한다.
4. **30라운드 비용 관리.** 1–10 마을 입구, 11–20 오염된 골목, 21–30 둥지 앞의 세 구간을 팔레트·소품·표식 조합으로 구분한다. 맵 30장이나 새 몬스터 30종을 만들지 않는다. 기존 배경 레이어·타일·스프라이트를 우선 재사용하고, 구간별 고유 표식 하나부터 추가한다. 라운드 구성이나 난이도는 이 아트 작업에서 변경하지 않는다.

## P0 — 전체 캐릭터 출시용 리드로우

배경 시안과 병행해 대표 캐릭터를 먼저 그린다. 출시 범위에는 `data/units/units.json`의 아군 5종, 일반 적 8종, 보스 6종, `data/heroes/hero_captain.json`의 영웅이 들어간다. 제빵사·일꾼처럼 목록 밖에서 직접 불러오는 캐릭터도 씬과 아틀라스에서 찾아 포함한다. 후반 보스가 기존 아트를 공유하는지는 먼저 확인하고, 공유하더라도 출시판에서는 머리·몸통·공격 도구 중 하나 이상을 멀리서 구별할 수 있게 그린다.

1. **스타일을 먼저 확정한다.** 영웅, 식빵병, 일반 적 하나, 보스 하나를 같은 전투 프레임에 놓고 두 방향을 비교한다. 추천은 밝은 빵 속살과 구운 테두리, 앞치마와 주방 도구를 살린 아군과, 차갑고 불규칙한 포자·균사 형태의 적이다. 빛 방향, 외곽선 두께, 색 단계, 눈과 표정의 최소 픽셀 규칙을 한 장으로 정한다. 배경과 겹쳤을 때 또렷하면서 가까이서 봐도 표정과 재질이 매력적인 쪽을 고른다.
2. **역할마다 실루엣을 새로 그린다.** 식빵병은 칼과 네모난 빵 몸통, 원거리는 투사체를 던지는 자세, 탱커는 넓고 낮은 몸과 방패, 빠른 유닛은 앞으로 쏠린 자세, 공성은 큰 장비로 읽히게 한다. 적도 돌진·포격·폭발을 서로 다른 몸짓으로 예고한다. 색만 바꾼 스프라이트로 역할 차이를 대신하지 않는다. 영웅과 보스는 큰 형태와 표정에 가장 많은 제작 시간을 쓴다.
3. **움직임과 초상화까지 맞춘다.** 대기·이동·공격·피격·퇴장은 각 캐릭터가 실제로 쓰는 상태를 기준으로 작업한다. 공격은 준비→접촉→회복 자세를 구별하고, 발 기준점과 실제 타격 프레임은 유지한다. 카드·도감 초상은 같은 캐릭터의 얼굴과 도구를 사용하되, 전신을 작게 줄여 알아보기 힘들게 만들지 않는다.
4. **리소스는 공유하되 결과를 검수한다.** 같은 체형의 걷기 타이밍과 팔레트 규칙은 공유하고, 새 프레임은 실루엣과 공격 예고에 집중한다. `char_player`, `char_boss_*`, `tools/art/layout_lock`, `tools/art/char_quality.py`를 출발점으로 삼는다. 이름·프레임·피벗 등 아틀라스 계약과 텍스처 용량을 확인한다. 모델에는 시안 비교, 생성기·아틀라스 적용, 검수를 맡기고 최종 픽셀 정리는 실제 아트를 보고 손본다.
5. **출시 판정은 실제 크기로 한다.** 초반·중반·보스 전투에서 1x/축소/흑백, 같은 유닛 밀집, 양 진영이 겹친 순간, 카드와 본체를 비교한다. 이름표를 가려도 진영과 주요 역할이 읽히고, 발 떨림·잘린 프레임·공격 판정 불일치가 없어야 한다. 역할별 전후 시트와 전투 클립을 남긴다. 대표 4종의 스타일을 고른 다음 전체 라인업으로 확장하며, 아틀라스 검사 통과만으로 출시 품질이라 판정하지 않는다.

## P1 — 나머지 화면

- **타이틀:** [기존 메뉴](../qa/windows-polish/menu.png)는 로고와 시작 버튼이 선명하지만 뒤쪽이 넓은 띠로만 구성돼 있다. 빵집 창 불빛과 멀리 보이는 둥지 실루엣으로 게임의 갈등을 한 장면에 보여준다. 전투 배경 소품을 재사용하고 로고 뒤 대비는 낮춘다. `scenes/ui/main_menu.tscn`, `ui_title_ko/en` 아틀라스 확인.
- **라운드 선택:** 30개를 한 화면에 밀어 넣지 말고 구간별로 묶는다. 현재 진행, 잠금, 별, 보스 표식을 서로 다른 모양으로 보여주고 이어하기가 한눈에 보여야 한다. `scenes/ui/round_select.tscn` 확인.
- **강화:** 현재 효과 → 강화 후 효과와 가격을 한 줄에서 비교한다. 재화 부족, 구매 가능, 최대 레벨은 색과 문구를 함께 쓴다. 패배 뒤 들어왔다면 재도전으로 돌아가기 쉽게 한다.
- **결과:** [기존 승리 화면](../qa/store_captures/store_06_result_ko.png)은 승리 제목과 통계가 명확하지만 넓은 판이 전장을 대부분 덮는다. 승리는 다음 라운드, 패배는 다시하기를 주 버튼으로 삼고 강화는 가까이 둔다. 별·보상·시간을 위쪽에 모으고 나머지는 접어 전투가 끝난 장면을 조금 남긴다.
- **설정·일시정지:** 음량은 현재 %가 바로 보이게 하고, 0%·100%·저장 후 재시작을 검사한다. 컨트롤과 배경의 대비를 맞추고 한·영 문구, 키보드 포커스, 취소 동작을 확인한다.
- **유닛·이펙트·스토어:** 아군은 빵 껍질·앞치마·도구, 적은 포자·갓·균사로 진영을 구별한다. 역할별 차이는 무기와 몸통 비율부터 잡고 카드에도 같은 실루엣을 쓴다. 스토어 캡처는 실제 배포 후보 빌드가 나온 뒤 갱신한다.

## 작업 순서와 검수

1. 같은 SHA에서 첫 전투, 밀집 전투, 보스, 양쪽 기지, 메뉴, 라운드 선택, 강화, 설정, 승리·패배를 기록한다. R01/R06/R10을 기존 비교 기준으로 쓰고 R20/R30은 현재 데이터에서 접근 가능할 때 추가한다. 전투 전후의 카메라·웨이브·유닛 수·언어·화면 크기를 고정한다.
2. 배경 두 시안을 같은 전투 프레임으로 만든 뒤 1x, 축소 화면, 흑백에서 비교한다. 유닛·위험 신호가 먼저 읽히는 안을 고른다. 첫 구현은 배경 한 구간과 두 기지까지로 제한하고 그 결과로 나머지 구간의 팔레트와 타일 규칙을 정한다.
3. HUD는 배경과 별도 변경으로 비교한다. 640×360, 1280×720, 1920×1080, 좁은 가로 창, 비정수 배율, 실행 중 리사이즈를 본다. 한·영 최장 카드 이름, 보스 바+안내 중첩, 버튼 입력이 가려지는 경우를 포함한다. 모바일은 실기기 결과를 별도 기록한다.
4. 각 변경에 전후 캡처, 입력 결과, 드로우콜·프레임 시간·아틀라스 용량 전후값을 붙인다. 수치는 같은 조건에서 비교하고 미측정은 표시한다. 데스크톱 창 활성화나 입력이 필요한 검수는 사전 허락을 받는다. 저장된 캡처와 헤드리스 검사를 먼저 쓴다.

## Fable에 넣을 첫 지시

> 이 문서와 링크된 로컬 캡처, `battle_view.gd`, `pixel_camera.gd`, `tools/art/biome.py`, `hud_layout.gd`를 읽어라. 가장 큰 문제인 ‘밭과 건물의 반복 무늬가 유닛보다 먼저 보인다’를 기준으로 배경 두 시안을 같은 전투 프레임으로 비교해라. 배경만 바꾼 결과와 카메라까지 조정한 결과를 구분하고, 선택 근거를 1x·축소·흑백에서 보여줘라. 첫 변경은 1구간과 양쪽 기지에 한정하고 전투 좌표·저장·난이도는 유지해라. 같은 조건의 전후 이미지와 드로우콜·아틀라스 용량을 첨부해라. 창 활성화와 마우스·키보드 조작은 하지 마라. 해당 증거를 얻을 수 없으면 미검증으로 표시해라.
