# 100라운드 독립 확장 인수인계

기준 커밋: `28905c1`. 작업 브랜치: `codex/campaign100-roster10`.
클로드 작업 중인 원본 체크아웃의 미커밋 변경은 가져오지 않았다. 이 브랜치는 별도 합병용이며 main에 합치지 않는다.

2026-11-13 사용자 요청으로 추가 테스트는 일괄 검사 때까지 보류했다. Windows 빌드는 완료했으며 실행 검사는 생략했다. 완료한 검사와 남은 항목은 [검증 현황](CAMPAIGN100_TEST_STATUS.md)에 기록했다.

## 구현 범위

- R1~R100 연속 진행. R30→31, R40→41이 이어지고 R100에서 종료한다. 라운드 선택은 10페이지다.
- 출전 병종 10종, 편성 1~5종. 영웅과 생산 일꾼은 편성 슬롯에서 제외한다. 신규 유닛 5종은 R8/11/14/17/20에 무료 해금한다.
- 바게트: 긴 근접 사거리. 마카롱: 장거리 단일 공격. 고추빵: 광역 공격. 도넛: 높은 HP·고정 방어력. 와플: 기지 공격 특화.
- 신규 유닛은 `roster10` PNG 아틀라스의 대기·이동·공격·죽음 애니메이션과 24×24 초상을 갖는다(`tools/art/release_slice/roster10_sheets.py`, 원본과 프롬프트는 `docs/art/release_slice/unit_regen/`). 기존 보스·배경·HUD 아트 파일은 편집하지 않았다.
- 모든 강화 항목 최대 40레벨. 기존 1~9레벨 비용·효과를 보존하며, 일꾼의 기존 상한 8레벨 이후도 확장했다. 늦은 레벨 HP·공격력은 덧셈 성장에 6% 복리 계수를 추가한다. 생산·자원 계열은 덧셈 성장이다.
- R23/42/61/79/96 성장 관문. 기존 보스와 호위를 조합한다. 모든 계정은 같은 적 데이터를 사용한다.
- 3,000/8,000/12,000/16,000/22,000원 기준의 1회성 확정 골드 팩. 현재는 테스트 상점만 구현했고 실제 결제는 연결하지 않았다.

R41~R100은 기존 후반 전장의 적 패턴·배경을 기반으로 성장 수치·보상·보스 관문을 확장한 콘텐츠다. 새 배경 60종을 제작한 것은 아니다. 경쟁작 조사·가격 근거·누적 지출은 [BM 조사](CAMPAIGN100_BM_RESEARCH.md)를 참조한다.

## 사용 방법

독립 작업 폴더 루트의 `BakeryKnights.exe`를 실행한다. 라운드 선택 화면 왼쪽 위 **편성**을 열고 1~5종을 골라 **편성 저장**을 누른다. 저장된 유닛은 다음 전투와 재도전에 반영된다. 이미 해금한 후반 유닛은 이전 라운드에도 데려갈 수 있다.

테스트 실행파일의 골드 상점에서 **성장 팩**으로 전환하면 관문별 상품을 확인한다. 표시된 금액은 설계 가격이며 실제 결제는 발생하지 않는다. 일반 골드 탭은 기존 테스트 기능으로, 밸런스 측정에서는 일반 골드 구매를 사용하지 않았다.

독립 실행파일은 `BakeryKnights-Campaign100` 사용자 데이터 폴더를 사용한다. 소스의 정식 저장 경로는 바꾸지 않았고, 빌드 스크립트의 `-UserDataName BakeryKnights-Campaign100` 옵션을 통해 패키지에만 적용한다. 원본 폴더의 `BakeryKnights.exe`는 교체하지 않는다.

## 난도와 보상 재생성

`tools/build/generate_campaign100.py`는 기준 커밋의 데이터를 읽어서 생성하므로 여러 번 실행해도 배율이 중복 적용되지 않는다. 기존 R1~R22를 보존하고 R23 이후 곡선을 확장한다. `data/campaign100_tuning.json`의 관문 계수는 측정 결과로 조정한다. **병합 후에는 생성기를 그대로 실행하지 말 것:** 기준 커밋이 고정되어 있으므로 클로드가 이후 바꾼 라운드/문구를 덮어쓸 수 있다. 통합 시 생성기 입력 기준과 변경 보존 방식도 함께 갱신한다.

- R24~40 누적 계수: HP `1.018^(round−23)`, 공격력 `1.012^(round−23)`.
- R41 이후 HP: `1.82 × 1.018^17 × 1.027^(round−40)`.
- R41 이후 공격력: `1.442 × 1.012^17 × 1.020^(round−40)`.
- 관문은 해당 기본값에 HP 1.28·공격력 1.16과 보정 후보 계수를 추가한다. 공격력에는 관문 계수의 제곱근을 사용한다. 최종 60Hz 독립 검증은 보류 상태다.
- 강화 HP·공격력: `base × (1 + per_level × (level−1)) × 1.06^max(0,level−9)`.
- 기존 마지막 강화 비용 이후 약 11.5%씩 비용 증가, 10골드 단위 반올림.
- 일반 반복 승리 보상은 유지한다. 결제하지 않고 반복 플레이로 같은 강화 재화를 모을 수 있다.

실제 데이터 전부는 [경제표](balance/campaign100_economy.csv)로 추출한다. 가격은 적 난도 계산의 입력이 아니다. 상품을 받은 직후 다른 적 배율을 적용하는 코드도 없다.

## 검증 재현

공용 PC에서는 반드시 `coordination/heavy_run_detached.ps1`로 아래 명령을 담은 작업 파일을 실행한다. 이 작업 공간에는 원본의 실행 잠금 스크립트를 `build/heavy_runner`에 복사해 사용했으며, 무시되는 로컬 파일이라 커밋하지 않는다. 원본 작업을 중단하거나 공용 잠금을 우회하지 않는다.

```powershell
& ./tools/build/verify_campaign100.ps1 -Godot '<Godot console exe 절대 경로>' -Balance
```

검증은 격리한 APPDATA를 사용한다. 편성 제한·저장 실패 롤백·구매 중복 방지·100라운드 참조·실제 App/HUD 연결·기존 전투/저장 동작을 검사한다. 밸런스 탐색은 `tests/acceptance/calibrate_campaign100.gd`, 독립 표본과 전체 라운드 검사는 `tests/acceptance/validate_campaign100_balance.gd`다.

관문 비교의 예산 가정: 이전 스테이지 최초 클리어+3성 보상을 각 1회 받은 상태, 처치 골드·반복 파밍 제외, 출전 5종+영웅·생산·일꾼·기지에 저렴한 강화부터 투자한다. 보정 탐색은 30Hz, 최종 검증은 실제 게임과 같은 60Hz, 최대 600초다. 기본 5종 덱을 사용한다. `journey_campaign100.gd`는 별도로 실제 별 개수·처치 골드·최초 클리어 보상을 누적하고 강화 상태를 유지하며 진행한다. 이 모형은 실제 사람의 결제 전환율이나 모든 편성의 승률을 증명하지 않는다. 새 병종은 배치·실제 공격·역할 차이를 검사하고, 전체 조합 252개의 장기 성장률은 별도 사람 플레이테스트 대상으로 남긴다.

## 나중에 합칠 때

1. 클로드의 보스·배경·HUD 변경을 먼저 보존한 상태에서 이 브랜치 커밋을 적용한다.
2. `src/gameplay/battle.gd` 충돌 시 이 작업의 변경은 `start(..., loadout: Array = [])`와 `sim.setup(..., loadout)` 전달 두 곳이다. 클로드의 나머지 연출 코드를 유지한다.
3. `src/core/app.gd`의 roster 화면 경로와 `Save.selected_loadout()` 전달을 가져온다. `Content` 로스터 검증, `Save` 편성/상품 저장, `BattleSim` 성장 공식을 함께 적용한다.
4. `assets/manifest.json`에는 `roster10` 아틀라스 등록과 신규 5종 매핑만 추가한다. 기존 아틀라스·보스 매핑을 덮어쓰지 않는다. `src/art_preview/slice_adapter.gd`, `src/ui/hud.gd`, `hud_layout.gd`, `battle_view.gd`는 이번 작업에서 변경하지 않았다.
5. `src/ui/ui_style.gd`는 신규 `card_` 아이콘 경로만 추가한다. `round_select.gd`는 편성 진입 버튼을 추가한다. 기존 HUD 그림을 교체하는 변경은 없다.
6. 라운드의 보스 사용처를 클로드 쪽과 대조한다. 성장 관문에 기존 보스를 추가했으므로 보스 6종 계약과 최종 사용 라운드를 함께 재검토한다.
7. `data/text`, `meta`, `rounds`, 신규 유닛 데이터와 테스트를 적용한다. `export_presets.cfg`의 신규 아틀라스 JSON 포함 필터를 빠뜨리지 않는다.
8. 통합 후 격리 테스트와 Windows 빌드를 다시 수행한다. 이 독립 빌드는 클로드의 아직 미커밋인 연출 결과를 포함하지 않는다.

빌드 출력·개인 로그·엔진·세이브는 Git에 넣지 않는다. 이 소스 커밋은 GitHub Release 배포가 아니다.
