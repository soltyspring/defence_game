# 도전 챕터 R31–R40 "둥지 심부" — 설계와 인수인계

2026-11-11 · 기준 `9b730fd` 위의 미커밋 작업 트리. **R31–R40 모두 구현·활성화.** 아래 1–8절은 Fable이 대표 전투 세 개를 만든 시점의 인수인계다. 현재 변경과 Windows 검증은 9절을 참고한다.
봇·스크립트 결과는 사람의 플레이 평가가 아니다.

## 2. 새 규칙 (유닛 데이터 키, `src/gameplay/battle_sim.gd`)

세 키 모두 없으면 기존 동작과 같다. R01–R30의 유닛은 쓰지 않는다.

### `heavy` — 예고 → 큰 공격 → 회복
```json
"heavy": {"interval": 7.0, "first": 2.5, "windup": 1.4, "radius": 44, "offset": 20,
          "power": 7.0, "knockback": 60, "recover": 2.4, "exposed_mult": 2.2, "structure_mult": 1.0}
```
- `interval`초마다(첫 번째는 `first`초 뒤) 사거리 안에 상대가 있으면 `windup`초 동안 예고한다. 바닥에 구역 표시가 생기고 `heavy` 이벤트가 나간다.
- 구역은 예고가 시작될 때 `x + 진행방향 × offset`, 반경 `radius`로 **고정**된다. 그 안에 남아 있는 상대만 `atk × power` 피해와 `knockback`을 받는다. 기지가 구역 안이면 `structure_mult`를 곱해 맞는다.
- 그 뒤 `recover`초 동안 움직이지도 공격하지도 않고, 받는 피해가 `exposed_mult`배가 된다.
- 예고 중에 죽거나 연결이 끊기면 공격은 취소되고 구역 표시도 사라진다.

### `link` — 균사 연결
```json
"link": {"radius": 110, "damage_taken": 0.4, "max_links": 3, "prefer_boss": true,
         "break_stagger": 1.2, "break_exposed": 1.4, "break_exposed_s": 3.0}
```
- 살아 있는 연결원은 `radius` 안의 가까운 아군 `max_links`명(보스 우선)이 받는 피해를 `damage_taken`배로 줄인다. 연결원끼리는 보호하지 않는다.
- 연결원이 죽으면 묶여 있던 적은 `break_stagger`초 공격이 늦어지고, `break_exposed_s`초 동안 피해를 `break_exposed`배 받는다. 예고 중이던 큰 공격은 취소된다.

### `hold_behind` — 앞줄 뒤에 머무르기
`"hold_behind": 45` — 자기 편 맨 앞 유닛보다 45px 이내로 다가가지 않는다. 앞에 아무도 없으면 일반 유닛처럼 전진한다.

### 연결을 끊는 수단 (새 조작 없음)
매듭은 앞줄 45px 뒤에 서므로 근접·원거리 병사의 자동 공격은 닿지 않는다. 닿는 것은 영웅의 밀대 내려찍기(영웅 앞 90px), 빵가루 포격(맨 앞 적 기준 반경 80), 그리고 앞줄이 무너진 뒤의 일반 공격이다. 특정 병사를 강제하지 않는다. 끊지 않고 밀어붙여도 앞줄이 죽으면 매듭이 드러난다.

### 화면 표시 (`battle_view.gd`, 임시 도형)
구역 표시는 양 끝에서 차오르는 바닥 띠(가득 차면 타격), 예고 중인 적은 뒤로 젖히며 머리 위 쐐기가 커지고, 빈틈인 적은 가슴 높이에 밝은 고리가 뜬다. 연결은 매듭에서 늘어진 선으로 그린다. 토스트: `toast.enemy_heavy`(전투당 1회), `toast.boss_heavy`, `toast.link_break`. HUD 스냅샷 `boss`에 `telegraph`·`exposed`·`linked`가 추가됐다(아직 HUD에서 쓰지 않음).

## 4. 대표 전투

- **R31 균사의 문턱** (길이 1500): 호위병만 나온다. 14초에 1명, 44초에 2명, 80초에 3명, 120초에 4명. 첫 호위병이 느리게 걸어오는 동안 제빵사에 투자할지 병사를 먼저 뽑을지 고른다.
- **R35 얽힌 호위대** (길이 1900): 호위병 + 매듭. 세 번째 웨이브에만 이전 챕터의 질주자 4명이 보조로 섞인다.
- **R40 둥지의 핵** (길이 2260): 12초에 보스와 호위병 1명. 이후 웨이브는 호위병 + 매듭. 예고 중에 매듭을 끊으면 내려찍기가 취소되고(지금 막기), 그냥 물러났다가 빈틈에 스킬을 모을 수도 있다(기다렸다 집중). 매듭이 살아 있으면 빈틈의 가치가 절반 이하다.

## 5. R32–34·R36–39를 채우는 규칙

1. 파일은 `data/rounds/r31.json`을 복사해 `id`·`index`·`name`·`name_key`·`waves`·`trickle`·보상만 바꾼다. `chapter: 4`, `biome: "biome_nest"`, `challenge: true`, `enemy_scaling`은 그대로 둔다. 난이도는 수치가 아니라 조합과 간격으로 올린다.
2. 웨이브 한 덩어리 = **호위병 2–4명당 매듭 0–2개**. 매듭이 호위병보다 많으면 연결이 남아돌 뿐이다(매듭 하나가 3명까지).
3. 호위병의 `interval`은 2.5초 이상. 더 촘촘하면 예고 구역이 겹쳐 물러날 자리가 없어진다.
4. 이전 챕터의 적은 한 라운드에 한 웨이브, 한 종, 5명 이하로만 보조에 쓴다.
5. 매 라운드 변주는 하나만 넣는다. 권장 순서:

| 라운드 | 변주 |
|---|---|
| R32 | 호위병 2명이 6초 간격으로 따로 온다 → 빈틈이 번갈아 생긴다 |
| R33 | 매듭 첫 등장을 여기로 당길지 검토. 아니면 호위병 + 부푼 효모(예고 중 폭발) |
| R34 | 호위병 3명이 2.5초 간격으로 붙어 온다 → 구역이 이어진다 |
| R36 | 매듭 2개가 같은 호위대를 나눠 감싼다 → 하나만 끊으면 절반만 풀린다 |
| R37 | 매듭 + 포격수 보조 → 뒤를 끊을 이유가 둘이 된다 |
| R38 | 트리클에 매듭을 넣는다 → 전투 내내 연결이 다시 생긴다 |
| R39 | R40 예행: 호위병 대열 + 매듭 3개, 보스 없음 |

웨이브 예시 (R36):
```json
{"at": 46, "spawns": [
  {"unit": "e_thrall", "count": 4, "interval": 3.0},
  {"unit": "e_binder", "count": 2, "interval": 5.0}
]}
```
새 적을 더 만들 때는 색·체력 변종 말고 위 세 키의 다른 조합으로 만든다. 예: `heavy`만 있고 빠른 돌진병(`offset` 크게, `radius` 작게), `link`의 `damage_taken`이 1보다 큰 "약점 공유" 매듭.

## 6. 해금·저장·개발 경로

- `data/rounds/order.json`의 `challenge`: `{"enabled": false, "rounds": ["r31" … "r40"]}`.
- **`enabled`가 true이고 열 개 파일이 모두 있을 때만** R31–R40이 플레이어의 라운드 순서에 붙는다. 그 전에는 라운드 선택에 보이지 않고 해금되지도 않는다. `enabled`만 켜고 파일이 빠져 있으면 경고를 내고 닫힌 채로 둔다.
- 챕터가 열려도 R30 결과 화면에는 "다음 라운드"가 없다(본편 엔딩 유지). R31은 라운드 선택 4쪽에서 들어간다. R30을 클리어한 저장은 R31이 열리고, 클리어하지 못한 저장은 잠겨 있다. 기존 해금 규칙(앞 라운드에 별이 있으면 열림)을 그대로 쓴다.
- **개발 경로**: `--round=r31` (또는 r35, r40). 순서에 없는 라운드는 이 인자로만 시작된다. 결과는 `dev_round: true`로 표시되고 코인·별·해금·튜토리얼 기록을 저장하지 않는다. 다시하기는 되고 다음 라운드는 없다.
- 챕터를 여는 절차: 일곱 파일 추가 → `enabled: true` → `test_campaign30.gd`의 "30라운드·3쪽" 검사를 40·4쪽으로 고친다.
- 데이터가 바뀌어 콘텐츠 버전이 달라졌다. 기존 저장은 처음 불러올 때 기존 콘텐츠 마이그레이션을 한 번 거친다(진행·별·강화 유지 확인).

## 8. 검증

Linux용 Godot 4.7.2 디버그 템플릿을 헤드리스로 직접 실행했다. 이 바이너리는 `-s`를 받지 않아 테스트 스크립트를 노드로 감싸 돌렸다(프로젝트에는 넣지 않음). Windows에서 `-s`로 돌린 결과는 아니다.

- `tests/acceptance/test_challenge_core.gd` — **252/252 통과.** 데이터·규칙·R35 두 방법·보스·해금/저장·개발 경로.
- 기존 회귀: 캠페인 390/390, 폴리시 29/29, 품질 57/57, UI 3,415/3,415, Fable 핵심 59/59, 대형 6/6, 수락 스위트 112 PASS / 0 FAIL / 2 NOT_TESTED. 수락 스위트의 flow 묶음은 이 실행 방식에서 돌지 않아 빠져 있다.
- R01·05·08·10·14·20·25·30을 바꾸기 전 시뮬레이션과 같은 봇·시드로 돌려 종료 시각·기지 체력·처치 수·밀가루까지 모두 같았다.

강화 레벨별 R40: 6레벨은 두 봇 모두 패배, 7레벨부터 승리(무시 봇 영웅 사망 3, 대응 봇 0). 같은 6레벨에서 R30은 359초에 기지 62%로 이긴다. R31에서 제빵사 0·3·8명을 목표로 한 봇은 각각 100·94·113초에 이겼다.

**확인하지 못한 것**
- 사람이 플레이했을 때의 난이도와 예고의 가독성. 화면을 캡처하지 못해 표시 도형은 "오류 없이 그려진다"까지만 확인했다.
- 9레벨에서는 예고를 무시해도 세 라운드를 모두 이긴다. R35·R40에서 대응 봇이 더 느린 것은 물러나는 동안 영웅의 공격과 오라를 잃기 때문이다. 대응이 시간으로도 이득이 되게 하려면 수치 조정이 더 필요하다.
- Windows 네이티브 실행, 새 토스트의 실제 HUD 표시, 효과음(예고·연결 끊김 전용 소리 없음), `biome_nest` 색조의 실제 모습.

## 9. Codex: 열 라운드 통합과 실행 검증

- R32는 번갈아 오는 호위병, R33은 단일 매듭 소개, R34는 연속 예고, R36은 이중 연결, R37은 포격 엄호, R38은 다시 생기는 연결, R39는 세 매듭을 둔 보스 예행이다. 기존 R01–R30의 웨이브·난이도는 그대로다.
- 본편 R30 결과는 기존 엔딩을 유지한다. 4쪽의 R31이 열리고, 일반 플레이에서는 직전 라운드를 깰 때마다 다음 전투가 열린다. `--round=r40` 같은 도전 전투 미리보기는 활성화 이후에도 진행을 저장하지 않는다.
- 호위병·매듭·둥지의 핵은 공용 `char_challenge` 아틀라스의 별도 스프라이트다. 호위병과 핵은 준비·내려찍기·회복 자세가 각각 있고, 바닥 예고와 연결선도 유지했다. 아틀라스는 도전 적이 있는 전투에서만 불러온다. 재생성: `python tools/art/chars_challenge.py`.
- 새 효과음: `nest_windup`(상승하는 두 음), `nest_slam`(낮은 타격과 잔해음), `nest_link_snap`(짧은 끊김). 재생성: `python tools/audio/synth.py --only=nest_windup,nest_slam,nest_link_snap`. 파형 검증에서 작은 스피커 대역이 약했던 타격과 기존 밀가루 배달음을 보강했다. 전체 오디오 파일 검증 통과. 실제 스피커에서의 청감은 미검증.
- 강화 7레벨 봇, 같은 시드 101: 두 전략 모두 10개 라운드에서 승리했다. R39는 무시 381초·기지 28%·영웅 사망 2회, 대응 246초·기지 100%·사망 0회. R40은 무시 369초·사망 3회, 대응 385초·사망 0회. 대응의 이득을 모든 라운드에서 더 빠른 클리어로 가정하지 않는다. R40의 수치는 사람 플레이 없이 더 올리지 않았다.
- 격리한 가상 화면에서 찍은 Godot 렌더는 `build/challenge-render/`에 있다(R31/R35/R40 예고, R40 핵 노출). 실제 플레이나 Windows 창 입력의 증거가 아니다.
- Windows Godot 4.7.2 헤드리스: 도전 핵심 309/309(세 새 효과음이 전투 이벤트에서 믹서까지 재생되는지 포함), 캠페인 391/391, 전체 수락 156 PASS·0 FAIL·2 NOT_TESTED. 전체 수락의 미검증 항목은 전반적인 오디오 큐 통합과 Android 실기기다. 로그: `build/windows/challenge-final/`.
- 로컬 Windows x64 내장 데이터 EXE: `build/windows/challenge-final/BakeryKnights-Challenge-Preview.exe`. 헤드리스 메뉴 및 R40 진입, 챕터 아틀라스·오디오 로드를 확인했다. 네이티브 창 플레이, 사람 난이도 및 기기 청감은 미검증. 원격 릴리스나 푸시는 하지 않았다.
